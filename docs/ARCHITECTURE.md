# Архитектура расширения

Chrome MV3, TypeScript. Исходники разбиты на модули, в поставке два файла (esbuild, IIFE): `dist/content.js` — на страницах hh.ru, `dist/background.js` — service worker для запросов к backend. Расширение перенесено из пользовательских скриптов Tampermonkey коллеги; старый код удалён, он остался в истории git.

Backend описан в [BACKEND.md](BACKEND.md), план доработок — в [ROADMAP.md](ROADMAP.md). Отбор вакансий, выбор резюме и письмо — только на backend (#27, решение владельца 2026-10-26): расширение откликается из очереди backend, а выдачу со страницы может отправить на сервер как запасной сбор.

## Модули

| Модуль | Ответственность |
|---|---|
| `content/main.ts` | composition root: собирает зависимости и панель |
| `core/controller.ts` | сборка: общий контекст шагов, конвейер, капча; после загрузки страницы передаёт управление подходящему шагу (`pickStep`) |
| `pages/step-context.ts` | `StepContext` (состояние, панель, конвейер, backend, `Navigator` вместо `location`), `PageStep`, `pickStep`, `stopQueue` |
| `pages/search-step.ts` | выдача → backend: карточки текущей страницы в `POST /api/import` (запасной сбор) |
| `pages/queue-step.ts` | режим «из очереди» |
| `pages/reject-step.ts` | чаты: следующий отказ, авто-отказы |
| `core/settings.ts` | настройки из панели: лимит, запасное письмо, сервер, поиск для выдачи, пробный режим |
| `report/report-actions.ts` | анкеты, отчёт CSV, «Аутлайн» и «Непонятное» |
| `core/state.ts` | состояние (режим очереди, outline, unclear) и `StateRepository` |
| `core/config.ts` | `AppConfig`, дефолты, `loadConfig`/`saveConfig` |
| `core/selectors.ts` | все селекторы и текстовые маркеры hh.ru |
| `core/delays.ts`, `core/daily-limit.ts` | задержки (`pause` — с разбросом ±30%, `wait` — для опроса), дневной лимит |
| `search/vacancy-collector.ts` | карточки выдачи для импорта на сервер (`ImportCard`), без отбора |
| `apply/` | конвейер отклика: распознавание исхода, письмо и отправка, `ApplyPipeline` |
| `pages/vacancy-info.ts` | данные со страницы вакансии |
| `resume/selector.ts` | выбор резюме в форме отклика по `match` профиля, выбранного backend |
| `letters/letter-provider.ts` | `LetterProvider`, шаблон с `{{title}}` и `{{company}}` |
| `report/` | отчёт по откликам и экспорт в CSV, извлечение стека, зарплаты, формата работы |
| `questions/` | сбор анкет работодателей, выгрузка JSON |
| `rejects/` | распознавание отказов и переход к следующему |
| `captcha/guard.ts` | детектор капчи: ставит очередь на паузу, решает человек |
| `dom/` | хелперы: `qs`/`qsa`, тип страницы, ввод в поля React |
| `infra/` | `KeyValueStorage` (Chrome и Memory), `Logger` с приёмниками |
| `ui/` | панель-оверлей, модалки, стили |
| `api/` | `BackendClient` (проверка связи, очередь, резюме, статусы, анкеты, импорт выдачи, события) и транспорт `executeApiRequest` |
| `queue/queue-mode.ts` | чистая логика режима «из очереди»: адрес страницы отклика, выбор следующей вакансии, исход → статус сервера |
| `background/main.ts` | service worker: принимает `{ type: "hh-api", path, method, body }` только от своего расширения, сам берёт адрес и ключ из конфига и делает `fetch` |

Зависимости идут сверху вниз: UI → шаги страниц и настройки → модули → `dom`/`infra`. Новый режим — новый `PageStep` и место в списке `pickStep` в `Controller.init`; шаги тестируются на подменном `StepContext` (`tests/steps.test.ts`). Ядро не обращается к `chrome.*` напрямую, только через `KeyValueStorage`, поэтому его можно тестировать без браузера.

## Связь с backend

Со страницы hh.ru запрос к `127.0.0.1` или к домашнему серверу Chrome блокирует (Local Network Access: ждёт разрешения пользователя, проверено 2026-10-24). Поэтому content script отправляет сообщение в service worker расширения, а тот делает запрос от имени расширения по `host_permissions` (`http://127.0.0.1/*`, `http://localhost/*`; адрес сервера за VPN — добавить туда же).

Адрес и ключ задаются в панели, блок «Сервер (backend)», и хранятся в `chrome.storage.local`. Сохранённый ключ в поле не подставляется: панель — часть DOM страницы, и её могут читать скрипты hh.ru. Кнопка «Проверить связь» проверяет адрес (`/health`) и ключ (`/api/stats`).

## Режим «из очереди»

Кнопка «Из очереди» в панели. Цикл:

1. `GET /api/queue` → первая вакансия, которую ещё не пробовали в этом запуске (`state.queueTried`).
2. Переход на `hh.ru/applicant/vacancy_response?vacancyId=…` — форма отклика сразу открыта; состояние режима (`queueRunning`, `queueCurrent`) хранится в `chrome.storage` и переживает переход.
3. Конвейер отклика; резюме — выбранное backend: перед переходом расширение берёт его `match` из `GET /api/resumes` (нет на сервере — остаётся выбор hh.ru); письмо — написанное backend (`coverLetter`), иначе шаблон. Анкета с ответами backend заполняется (см. «Анкеты»); без ответов — вопросы уходят на сервер, редиректа на поиск нет.
4. Исход → `POST /api/vacancies/{id}/status`: отклик — `Applied`, ошибка — `Failed`; анкета без ответов — `POST /api/vacancies/{id}/questionnaire` вместо статуса (нераспознанная — `Skipped`). Затем следующая вакансия.

Остановка: очередь пуста, сервер недоступен, статус не дошёл до сервера, кнопка «Отправить» неактивна, дневной лимит. Капча — пауза до решения человеком.

**Пробный режим** (галочка в панели, `config.queueDryRun`, по умолчанию включён): всё, кроме нажатия «Отправить», статусы на сервер не уходят. Вопросы анкеты уходят и в пробном режиме: это подготовка ответов, а не отклик. Выключается только явно, с подтверждением.

## Конфиг и хранение

Всё хранится в `chrome.storage.local`. Конфиг лежит под ключом `hh_autoapply_config` и содержит запасное письмо, дневной лимит, сервер, поиск для выдачи и пробный режим. `loadConfig` берёт только известные поля (настройки прежнего локального отбора отбрасываются), поэтому новое поле добавляется и в `DEFAULT_CONFIG`, и в `loadConfig`.

## Письма

- Универсальное письмо по умолчанию берётся при сборке из gitignored `letter.local.txt` (`define __DEFAULT_LETTER__`), потом правится в панели.
- Письмо под вакансию пишет backend (LLM, по шаблону резюме `LetterTemplate`); универсальное письмо из панели — запасное, если backend письма не прислал.

## Резюме

Резюме выбирает backend (правила поиска и LLM); профили резюме (`name`, `match`, ключевые слова) живут на сервере (`/api/resumes`). Расширение по `match` находит резюме в списке hh.ru. Если нужное резюме выбрать не удалось, вакансия пропускается.

## Выдача на сервер (#27)

Кнопка «Выдачу на сервер»: карточки текущей страницы выдачи без отклика (id, название, компания, сниппеты, формат, стек) уходят в `POST /api/import` в поиск, имя которого задано в панели («Поиск на сервере для выдачи»). Сервер оценивает их правилами этого поиска и LLM, импортные карточки подтверждает по странице вакансии при сборе. Это запасной путь, когда серверный сбор упёрся в антибот: выдача видна залогиненному браузеру.

## Сборка и запуск

```powershell
npm install
npm run typecheck; npm test
npm run build                  # dist/
node scripts/dev-browser.mjs   # Chromium с расширением, профиль .profile, CDP :9222
```

Браузер читает расширение только при старте, поэтому после сборки его перезапускают.

## Анкеты (#24)

Вопросы анкеты видны только со входом на hh.ru: без входа страница отклика ведёт на регистрацию, а страница вакансии — и публичная, и со входом — содержит только признак теста (`test.hasTests`, `testId`), без вопросов (проверено 2026-10-25). Поэтому вопросы присылает расширение:

1. В режиме «из очереди» конвейер встречает анкету без ответов → `questions/fill.ts` `toServerQuestions` собирает вопросы со страницы (`task-body`: вопрос, тип Radio / Checkbox / Text, варианты) → `POST /api/vacancies/{id}/questionnaire`. Вакансия на сервере — `Questionnaire`.
2. Backend (фоном после оценки или `POST /api/llm/answers`) отвечает LLM и возвращает вакансию в очередь с ответами (`questions[].answer`); неполный ответ — `Skipped` с причиной.
3. Следующий проход очереди: конвейер выбирает резюме, `fillQuestionnaire` заполняет анкету — вопрос сверяется по тексту после схлопывания пробелов, вариант — по тексту `[data-qa="cell-text-content"]` в `label[data-qa="cell"]` (клик по `input`), текст — нативным setter. Затем письмо и отправка; пробный режим не нажимает «Отправить».
4. Анкета на странице не совпала с ответами (на вопрос нет ответа или варианта нет) — не отправляется, вопросы уходят на сервер заново.

Признак анкеты на странице отклика — только блоки вопросов (`task-body`, `employer-asking-for-test`): подзаголовок «Для отклика необходимо ответить на несколько вопросов работодателя» hh.ru показывает и без анкеты (проверено вживую 2026-10-25). Во всплывающем окне — по-прежнему текст окна.

Текстовые вопросы анкеты лежат в той же обёртке `textarea-native-wrapper`, что и поле письма, — `getCoverLetterField` пропускает поля внутри `task-body`.

Разметка анкеты в тестах — `tests/fixtures/response-form.ts` (`questionnaire: true`), по живой странице.
