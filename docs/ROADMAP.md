# План доработок

Сводный план: что уже было запланировано в документах проекта и что предлагается сделать дополнительно по итогам разбора кода. Текущий статус для агентов — `.rules/context/task.md`; подробности по направлениям — `ARCHITECTURE.md`, `BACKEND.md`, `MULTI_ACCOUNT_PLAN.md`.

Обновлено: 2026-10-23.

## Где проект сейчас

| Часть | Состояние |
|---|---|
| Расширение | Работает на живом hh.ru: сбор, фильтры и скоринг, автоотклик, письма, автовыбор резюме, отчёт CSV, анкеты, автоотказы, дневной лимит, автопауза при капче. 29 тестов vitest |
| Backend | Поиски с правилами, оценка, выбор резюме, очередь, статусы, отчёт, импорт, Docker. 5 тестов xunit |
| Связь между ними | Нет: расширение и backend работают независимо |

Не проверено на живых данных: клик по выбору резюме в списке hh.ru, автопауза при капче, сбор через API hh.ru.

Блокеры: `api.hh.ru` отвечает 403 без токена приложения (регистрация на dev.hh.ru).

## Предлагается дополнительно

Найдено при разборе кода. Приоритет: 🔴 мешает следующим шагам, 🟡 снижает риск, ⚪ по желанию.

### Связка расширения и backend
- 🔴 **Один источник правил.** Фильтры и скоринг (`filter/rules.ts` ↔ `VacancyEvaluator`), извлечение стека (`report/extractors.ts` ↔ `StackExtractor`) и выбор резюме (`resume/profiles.ts` ↔ `ResumePicker`) реализованы дважды и уже расходятся: разные поля правил (`stopWords`/`requiredStack` против `ExcludeKeywords`/`IncludeKeywords`, на сервере есть `RequireSalary` и `SkipWithTest`), в ключевых словах резюме у расширения есть `wpf` и `wordpress`, у сервера нет. При переходе на P2 оставить правила на сервере, а в расширении — только режим без сервера или убрать дубли.
- 🔴 **Доступ расширения к API.** В `manifest.json` нет `host_permissions` для `http://127.0.0.1:8080`; в панели нет полей адреса сервера и ключа. Нужны для P1 и P2.
- 🟡 **CORS.** Сейчас `AllowAnyOrigin`; после связки ограничить источником расширения (`chrome-extension://<id>`).

### Backend
- 🟡 **Тонкие эндпоинты.** Импорт (оценка, дедупликация) и формирование CSV лежат в `Program.cs` — вынести в сервис в Infrastructure и форматтер в Core, как требуют правила проекта.
- 🟡 **Интеграционные тесты API** через `WebApplicationFactory` (`public partial class Program` уже есть): импорт, очередь, смена статуса, ключ `X-Api-Key`. Нужна БД для тестов — Testcontainers или SQLite (новая зависимость, согласовать).
- ⚪ Пагинация и фильтр по дате в `/api/report`; обновление уже известных вакансий при повторном импорте (сейчас пропускаются).

### Расширение
- 🟡 **Тесты на конвейер отклика.** Не покрыты `ApplyPipeline`, `submit`, `ResumeSelector`, `Controller` (416 строк). Сначала — HTML-фикстуры диалога отклика и списка резюме, затем тесты на исходы.
- 🟡 **Разделить `Controller`** по шагам страниц (`PageStep` для выдачи, вакансии, страницы отклика), как было задумано при переносе.
- 🟡 **Случайные паузы.** `DELAYS` фиксированные; человекоподобный разброс нужен до P9 и полезен уже сейчас. Меняет частоту запросов — согласовать с владельцем.
- ⚪ Единая версия: `package.json` и `manifest.json` — 0.4.0, поднимать вместе при релизе.

### Инфраструктура
- 🟡 **CI на GitHub Actions**: `npm run typecheck`, `npm test`, `npm run build`, `dotnet test`. Делать после первого push.
- ⚪ Линтер и форматтер (ESLint/Prettier, `dotnet format`) — новые зависимости, согласовать.
- ⚪ Перед публикацией репозитория вычистить из истории git старые скрипты с личными данными коллеги (`legacy/`).
