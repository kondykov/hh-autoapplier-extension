## Готово (typecheck, 83 vitest, 41 xunit, сборка, CI)
- Расширение: оверлей, сбор вакансий, фильтры и скоринг по пресетам, автоотклик, письма (универсальное + по пресетам), автовыбор резюме PHP/.NET, отчёт CSV, анкеты, автоотказы, повторы пустой выдачи, дневной лимит, автопауза при капче
- Backend: поиски с правилами, оценка, выбор резюме, очередь, статусы, отчёт, `POST /api/import`, автономный сбор с публичных страниц hh.ru (источники-плагины), Docker (postgres + api); архитектура DDD + CQRS без MediatR (4 проекта, OneOf, Scrutor, Scalar); клиент LLM (Groq, `openai/gpt-oss-120b`) и LLM-оценка вакансий: `Pending` → подходит / сомнительно / не подходит, журнал `LlmCalls`; письма под вакансию по резюме и его шаблону (`LetterTemplate`) — уходят в расширение с очередью
- Расширение ↔ backend: настройки сервера в панели, запросы через service worker, режим «из очереди» (пробный по умолчанию); `Controller` разделён на шаги страниц

## Осторожно
- Авто-режим переживает перезапуск браузера (`running` в chrome.storage): перед открытием страницы вакансии в dev-браузере проверить, что на кнопке панели «Авто», а не «Стоп»

## Блокеры и ограничения
- API hh.ru не используется (403 без токена); сервер читает публичные страницы hh.ru. Полный цикл в Docker проверен 2026-10-23: сбор → сохранение → оценка → очередь (5 вакансий по поиску «Blazor», удалённо)
- Антибот hh.ru при частых запросах с одного IP — сбор останавливается до следующего запуска
- Правила фильтрации в расширении работают только на выдаче; отфильтрованные не попадают в отчёт
- `Summary` и `LetterTemplate` у резюме не заполнены — владелец заполнит через `PUT /api/resumes` (без шаблона LLM пишет письмо сама, без подписи и контактов)
- В профиле браузера сохранено старое PHP-письмо — заменить в панели
- hh.ru на страницах отклика пишет «поменяйте видимость резюме» для резюме PHP — проверить видимость резюме
- Пробные прогоны очереди добавили 6 вакансий в «Аутлайн» расширения (у них анкеты) — при желании очистить кнопкой «Очистить»
