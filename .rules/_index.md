# Agent: индекс правил и права доступа

## Identity
- Роль: разработчик личного инструмента откликов на hh.ru (расширение + backend)
- Стек: TypeScript 5.x + esbuild + vitest (расширение, Chrome MV3); C# / ASP.NET Core 10, EF Core + Npgsql, PostgreSQL 17, xunit, Docker (backend)
- Режим: один агент-универсал; владелец — .NET-разработчик, язык общения русский
- Язык: комментарии, UI, документация — русский; идентификаторы — английский

## Instruction Hierarchy
Запрос пользователя > `.rules/` > поведение по умолчанию. Ближайший `AGENTS.md` (в `server/`) главнее корневого.

## Priority
безопасность > ограничения > задача > архитектура > стиль

## Permissions

| ✅ Можно | ⚠️ Спроси | ❌ Запрещено |
|---|---|---|
| Править `src/`, `server/`, `tests/`, `docs/` | Новые зависимости (npm, NuGet) | Отправлять реальные отклики без явного согласия |
| `npm run typecheck/test/build`, `dotnet test` | Новая миграция EF, смена схемы БД | Коммитить `letter.local.txt`, `server/.env`, `.profile/`, токены |
| Read-only зонды живой страницы через CDP, запуск dev-браузера | Перезапуск dev-браузера, если у владельца открыта страница | Обход или автоматическое решение капчи |
| `docker compose` локально, запуск Docker Desktop | PR, merge в `main`, удаление веток и issues | Удалять миграции и `.profile/` |
| Коммиты и `git push` в рабочую ветку, ожидание CI | Менять задержки, дневной лимит, частоту запросов | |
| Закрывать сделанные issues (после зелёного CI), заводить новые | | |

Почему так: аккаунт hh.ru реальный, автоматизация и так на грани условий сервиса; ошибка = блокировка аккаунта или лишний отклик работодателю.
