# Architecture: структура и решения

## Project Shape
Один репозиторий, два пакета.
- **Расширение** (`src/`): композиция в `content/main.ts`; оркестратор `Controller`; конвейер отклика; модули фильтров, резюме, отчёта, анкет, автоотказов, капчи, писем; панель-оверлей на странице hh.ru
- **Backend** (`server/`): DDD + простой CQRS — Domain (агрегаты) ← Application (команды/запросы + обработчики) ← Infrastructure (EF Core, источники вакансий, фоновый сбор) ← Api (контроллеры, `Auth/` — cookie входа и ключ `X-Api-Key`, Scalar)
- Поток: сборщик backend (источники-плагины) → оценка, выбор резюме, письмо → очередь → расширение откликается → статус обратно на сервер
- Сервер читает только публичные страницы, без аккаунтов; всё, что требует входа (отклики, статусы, переписка), делает расширение в браузере пользователя. Мультиаккаунта и Playwright-воркеров нет
- Цель (`docs/ROADMAP.md`): backend анализирует и оценивает (правила, LLM, резюме, письмо, ответы) для двух пользователей с RBAC; расширение собирает и исполняет одобренные отклики. Новую логику отбора и писем добавлять в backend, не в расширение

## Layers
| Слой | Ответственность | Зависит от |
|---|---|---|
| UI (`ui/`) | панель, модалки | controller |
| Core (`core/`) | оркестрация, состояние, конфиг | модули |
| Feature-модули | apply, search, filter, resume, report, questions, rejects, letters, captcha | dom, infra |
| DOM/Infra | хелперы DOM, storage, logger | — |

## Key Decisions
- **Два файла в поставке** (`dist/content.js` и `dist/background.js` через esbuild), модули в исходниках. Раньше был один файл (коллега считал мультифайловые расширения ненадёжными), но со страницы hh.ru Chrome не пускает запросы в локальную сеть — запросы к backend возможны только из service worker расширения
- **Ключ API не попадает в DOM страницы** — панель живёт на hh.ru, её DOM читают скрипты страницы
- **Расширение читается при старте браузера** — после сборки браузер перезапускают
- **Личное письмо подставляется при сборке** (`define __DEFAULT_LETTER__` из `letter.local.txt`) — чтобы не попадало в git
- **Резюме по стеку**: баллы по ключевым словам; ничья или ноль → остаётся выбор hh.ru; не удалось выбрать нужное → вакансия пропускается
- **Капча — человек**: детектор ставит авто-режим на паузу и ждёт, обход не делается
- **Backend отдельно**: фильтры и скоринг на сервере, клиент получает готовую очередь
- **Сбор с публичных страниц hh.ru** (`HhWebSource`) — `api.hh.ru` без токена приложения = 403, токена из браузера нет, регистрировать приложение владелец не хочет; публичная выдача отдаётся без входа и автономна
- **Источники — плагины `IVacancySource`** — потому что позже появятся другие агрегаторы
- **Импорт `POST /api/import`** — запасной путь
- **DDD + CQRS без MediatR, 4 проекта** — владелец хочет сам продолжать разработку; образец — его проект `Pp.HelperCrm.OrgsApi`, но со слоями-проектами (ADR 0001)
- **OneOf с именованным результатом на сценарий** — на .NET 11 переход на union-типы заменой одного объявления
- **PostgreSQL на 5433 на хосте** — 5432 у владельца бывает занят
- **`server/nuget.config` только с nuget.org** — в глобальном конфиге владельца недоступный приватный источник
